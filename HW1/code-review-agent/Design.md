# Design.md · 设计文档

## 1. 项目定位

一个基于 LLM Function Calling 的**代码审查智能体**：用户给出目标路径，Agent
自主浏览代码并产出结构化审查报告。不依赖任何 Agent 框架，核心循环手写实现，
便于展示 Agent 的设计模式与每一步的决策过程。

## 2. 总体架构

```
                ┌─────────────────────────────────────────┐
                │              main.py (CLI)               │
                │   review（单次）/ chat（交互，多轮记忆）   │
                └───────────────────┬─────────────────────┘
                                    │
                                    ▼
        ┌───────────────────────────────────────────────────┐
        │              CodeReviewAgent (agent.py)           │
        │                                                   │
        │   messages = [system, user, assistant, tool, ...]  │
        │                                                   │
        │   ┌────── Agent Loop（最多 max_turns 轮）─────┐   │
        │   │  LLM.chat(messages, tools)                │   │
        │   │    │                                       │   │
        │   │    ├─ 有 tool_calls ──► Tools.execute ──┐  │   │
        │   │    │                        结果追加到  │  │   │
        │   │    │                        messages ◄──┘  │   │
        │   │    │                        （继续循环）    │   │
        │   │    └─ 无 tool_calls ──► 输出最终报告        │   │
        │   └───────────────────────────────────────────┘   │
        └──────────────┬──────────────────────┬─────────────┘
                       ▼                      ▼
            ┌─────────────────┐    ┌──────────────────────┐
            │  LLMClient      │    │  Tools               │
            │  (llm.py)       │    │  (tools.py)          │
            │  指数退避重试    │    │  read_file           │
            │  408/429/5xx    │    │  list_files          │
            │  网络错误重试    │    │  search_code         │
            └─────────────────┘    │  check_syntax        │
                                   └──────────────────────┘
```

## 3. 模块设计

### 3.1 `main.py` —— CLI 入口
- `review <target> [-o report.md]`：一次性审查，结果打印并可选保存。
- `chat [-d dir]`：交互对话；`/reset` 清空记忆、`/exit` 退出。

### 3.2 `config.py` —— 配置
用 `dataclass` + `python-dotenv` 集中管理：API Key、模型名、接口地址、
重试次数（3）、工具输出上限（15000 字符）、最大循环轮数（15）。
`validate()` 在启动时快速失败，给出友好提示。

### 3.3 `llm.py` —— LLM 客户端（健壮性核心）
- 封装 OpenAI SDK 指向 DeepSeek 兼容接口（`base_url` 可换任意服务商）。
- **错误处理与重试**：网络错误、超时、HTTP 408/409/429/5xx 触发
  指数退避重试（1s → 2s → 4s，共 3 次）；4xx 参数错误直接抛出，不盲重试。

### 3.4 `tools.py` —— 工具集
四个工具，均按 OpenAI Function Calling Schema 声明：

| 工具 | 作用 | 设计要点 |
|------|------|----------|
| `list_files` | 项目结构树 | 跳过 `.git/venv/__pycache__` 等噪声目录；上限 200 行 |
| `read_file` | 读取代码 | 输出截断至 15000 字符，防止撑爆上下文 |
| `search_code` | 文本/正则搜索 | 返回 `文件:行号:内容`，上限 100 条 |
| `check_syntax` | Python 语法检查 | `py_compile` + 临时目录，不污染目标项目缓存 |

**安全设计**：`_safe_path()` 把所有相对路径解析到审查根目录内，
越界访问（如 `../../etc/passwd`，可被 Prompt 注入诱导）直接拒绝；
`execute()` 捕获一切工具异常并转为错误文本返回给 LLM——工具失败
不等于 Agent 崩溃，模型可以据此调整策略。

### 3.5 `agent.py` —— Agent 核心循环
- **系统提示词**定义角色、工作方式（先浏览后结论、禁止臆测）与输出结构
  （总体评价 / 🔴🟡🔵 分级问题清单 / 亮点）。
- **循环**：`messages` 追加用户输入 → 调用 LLM →
  - 有 `tool_calls`：执行并把结果以 `role=tool` 追加，进入下一轮；
  - 无 `tool_calls`：内容即最终报告，返回。
- **上下文记忆**：`messages` 会话内持久保留（含全部工具调用与结果），
  对话模式下多轮共享；`reset()` 可清空重来。
- **防失控**：`max_turns=15` 硬上限，超限则提示缩小范围。

## 4. 关键设计决策

1. **不用框架（LangChain 等）**：核心循环仅 ~40 行，行为完全透明可控，
   也便于在报告中展示 Agent 设计模式本身。
2. **审查目录作为沙箱根**：工具的"根目录"即审查目标，天然限制 LLM
   的文件访问范围，实现最小权限。
3. **结构化报告写入 System Prompt**：分级（严重/建议/风格）+ 位置 +
   影响 + 修改建议的固定格式，保证输出一致、可读、可评分。
4. **截断优先于报错**：所有工具输出都有上限。宁可丢失细节也不能
   让单次工具结果撑爆上下文窗口。

## 5. 限制与展望

- 目前 `check_syntax` 仅支持 Python，可扩展 ESLint/gofmt 等多语言检查。
- 无并行工具调用（逐个执行），可改为线程池并发。
- 可增加 `write_patch` 工具，让 Agent 直接产出修复补丁并回滚验证。
